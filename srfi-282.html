282: Additional R7RS (Type) Predicates

Abstract

Types and entities deserve predicates so that their user can meaningfully understand what they are dealing with, and usefully dispatch on them in their code. However, some R7RS “types” have no respective predicates. This SRFI defines them.

Rationale

The discussion of types in Scheme is often predicate-reliant, including in the in R7 “Disjointness of types” section. Types are reliably represented by their respective predicates. (This is, in part, why the author’s own SRFIs rely on predicates for typing.)

But more predicates are needed than R7RS Small provides. There are types that do actually exist (i.e. are programmatically reachable,) but have no predicates referring to their existence. Some implementations provide these predicates, but there’s no portable way to use them. Thus this SRFI: to have a common ground set of predicates for entities that otherwise exist in most Schemes. And implicitly exist in the standard too.

Specification

The whole SRFI is split into sub-libraries, one predicate per library. This is because not all implementations support first-class objects these predicates check. Portable code relying on this SRFI can thus do: 

(cond-expand
 ((library (srfi 282 environment)) #| Use environment? here|#)
 ((library (srfi 282 parameter))   #| Use parameter? here|#))

(srfi 282 environment) procedure (environment? object) → boolean

Returns true whenever given an environment object, as returned by environment and the like, and false otherwise.

(srfi 282 parameter) procedure (parameter? object) → boolean

Returns true whenever object is a parameter object, and false otherwise.

(srfi 282 continuation) procedure (continuation? object) → boolean

Returns true whenever object is a continuation (such as created by call/cc,) false otherwise.

Not Included

record? and record-type?. While records and their types are also part of the standard type repertoire, they have respective SRFIs, like SRFI-237 and SRFI-76.

Earlier versions of this SRFI contained library? and syntax-transformer? predicates, but these were removed as too meta and impossible to obtain in standard code.

Implementation

Sample implementation not provided yet.

The simplest conforming implementation might be: 

(define (environment? object) #f)
(define (parameter? object) #f)
(define (continuation? object) #f)
